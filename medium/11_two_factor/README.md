# Two Factor

## 🎯 1. Описание Бизнес-Задачи
Пароля недостаточно. Пользователь включает TOTP, подтверждает текущим кодом и только потом входит. Запасные коды выдаются один раз и сгорают после использования. Неверный код не создаёт сессию.

## ⚙️ 2. Обоснование Архитектурного Выбора
Код считается по RFC 6238 (HMAC-SHA1, шаг 30 секунд), а не сравнивается с зашитым `000000`. Секрет и запасные коды не хранятся открытым текстом: пароль и запасные коды — PBKDF2. Часы фиксированы, чтобы тест не зависел от секунды запуска.

## 🗄️ 3. СУБД и Хранилища Данных
Пользователи и запасные коды в SQLite. Секрет TOTP хранится в Base32, потому что так его показывают в приложении-аутентификаторе. В бою та же таблица на PostgreSQL.

## 🔄 4. Интеграции и Сложный Стек
- `GET /users/{id}/current-code` нужен песочнице, в бою его нет.
- Docker-порт `8111`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8111`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
