# Usage Quotas

## 🎯 1. Описание Бизнес-Задачи
Тариф даёт месячный лимит, а не просто частоту запросов в секунду. Списание внутри лимита уменьшает остаток. Запрос сверх лимита отклоняется, уже потраченное не откатывается. Закрытие периода обнуляет расход и открывает следующий месяц.

## ⚙️ 2. Обоснование Архитектурного Выбора
Это квота, а не rate limiter из коротких сервисов: проверяется сумма за период, а не интервал между вызовами. Проверка и увеличение `used` идут в одной транзакции, чтобы два параллельных запроса не проскочили лимит вместе.

## 🗄️ 3. СУБД и Хранилища Данных
Счётчики в SQLite. В бою тот же условный `UPDATE ... WHERE used + ? <= monthly_limit` на PostgreSQL. Redis здесь не заменяет учёт, потому что квота должна пережить рестарт.

## 🔄 4. Интеграции и Сложный Стек
- Ответ 429 с использованным и запрошенным количеством.
- Docker-порт `8109`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8109`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
