# Chat Rooms

## 🎯 1. Описание Бизнес-Задачи
Комната принадлежит участникам. Создатель уже внутри. Чужой не может писать, пока не войдёт. История идёт по порядку. Присутствие отдельно от членства: человек может быть в комнате и быть офлайн.

## ⚙️ 2. Обоснование Архитектурного Выбора
Сообщения нумеруются внутри комнаты, а не временем сервера: порядок тогда не зависит от часов. Проверка участника стоит до вставки сообщения. Это не общий Pub/Sub, а комната с историей.

## 🗄️ 3. СУБД и Хранилища Данных
Комнаты, участники и сообщения в SQLite. В бою история может уехать в PostgreSQL, присутствие — в Redis, правило «не член не пишет» остаётся.

## 🔄 4. Интеграции и Сложный Стек
- Docker-порт `8127`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8127`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
