# Subscriptions

## 🎯 1. Описание Бизнес-Задачи
Подписка начинается с пробного периода и не списывает деньги, пока срок не наступил. Когда период кончился, биллинг проводит оплату. Первый отказ переводит подписку в `past_due`. Второй отказ отменяет её. Успешная оплата снова делает её `active` и сдвигает дату продления.

## ⚙️ 2. Обоснование Архитектурного Выбора
Списание запускается явным `POST /billing/run`, а не скрытым потоком. Так видно, что триал не равен отмене и что повторный отказ — уже другой статус. Токен `decline` имитирует отказ банка без сети.

## 🗄️ 3. СУБД и Хранилища Данных
Планы и подписки в SQLite. Дата продления хранится явно, часы подменяются в тестах. В бою тот же прогон — задача Celery Beat по PostgreSQL.

## 🔄 4. Интеграции и Сложный Стек
- Пробный период задаётся на плане.
- Docker-порт `8108`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8108`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
