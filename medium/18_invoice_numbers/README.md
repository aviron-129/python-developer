# Invoice Numbers

## 🎯 1. Описание Бизнес-Задачи
Номер счёта идёт подряд и не переиспользуется. Аннулированный счёт остаётся в журнале со своим номером. Следующий счёт берёт следующий номер, а не дыру от аннулированного.

## ⚙️ 2. Обоснование Архитектурного Выбора
Счётчик и вставка счёта в одной транзакции. Номер не `MAX(number) + 1` по таблице счетов: аннулирование не должно сдвигать максимум назад, а гонка двух вставок не должна получить один номер.

## 🗄️ 3. СУБД и Хранилища Данных
Одна строка счётчика и таблица счетов в SQLite. В бою счётчик — последовательность PostgreSQL или строка с `UPDATE ... RETURNING`.

## 🔄 4. Интеграции и Сложный Стек
- Формат номера: `INV-0001`.
- Docker-порт `8118`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8118`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
