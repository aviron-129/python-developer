# Upload Pipeline

## 🎯 1. Описание Бизнес-Задачи
Клиент сначала получает разрешение на загрузку, потом отдаёт байты, и только после этого файл обрабатывается. Маленький PNG получает превью. Всё остальное отклоняется и не становится готовым.

## ⚙️ 2. Обоснование Архитектурного Выбора
Три шага разделены: намерение, сохранение, обработка. Так обработка не стартует на пустом файле. Проверка сигнатуры PNG локальная, без облака. В бою токен намерения был бы подписанной ссылкой в S3, статусы те же.

## 🗄️ 3. СУБД и Хранилища Данных
Статусы в SQLite, байты в памяти процесса. Для демо этого достаточно. В бою байты уходят в объектное хранилище, в таблице остаётся статус.

## 🔄 4. Интеграции и Сложный Стек
- Содержимое приходит в Base64.
- Docker-порт `8123`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8123`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
