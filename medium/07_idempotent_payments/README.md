# Idempotent Payments

## 🎯 1. Описание Бизнес-Задачи
Повторный клик «оплатить» не должен списывать деньги второй раз. Клиент передаёт `Idempotency-Key`. Тот же ключ и то же тело возвращают исходный платёж. Тот же ключ и другая сумма — конфликт, а не новое списание. Возврат можно сделать один раз.

## ⚙️ 2. Обоснование Архитектурного Выбора
Ключ связан с отпечатком тела запроса, а не только с идентификатором. Иначе клиент мог бы переиспользовать ключ успешной оплаты на другую сумму. Повтор отдаётся тем же объектом и заголовком `Idempotent-Replayed`.

## 🗄️ 3. СУБД и Хранилища Данных
Платежи в SQLite, ключ уникален. В бою та же таблица на PostgreSQL: уникальный индекс на ключ и сравнение хэша запроса.

## 🔄 4. Интеграции и Сложный Стек
