# Inventory Reservation

## 🎯 1. Описание Бизнес-Задачи
Два заказа не должны продать последние две кружки три раза. Резерв держит количество, не списывая его со склада. Commit забирает штуки со склада. Release возвращает их в доступные. Повторный commit уже отпущенного резерва отклоняется. Приёмка товара требует версию из `If-Match`, чтобы две одновременные приёмки не затёрли друг друга.

## ⚙️ 2. Обоснование Архитектурного Выбора
Оптимистичная блокировка через колонку `version`, а не долгий `SELECT FOR UPDATE`. Конфликт виден клиенту как 409, а не как тихая потеря обновления. Доступный остаток — это `on_hand - reserved`, а не отдельное поле, которое легко разъехалось бы.

## 🗄️ 3. СУБД и Хранилища Данных
SQLite. Условие `UPDATE ... WHERE version = ? AND (on_hand - reserved) >= ?` переносится на PostgreSQL без смены сценария. Redis-лок здесь не нужен: склад один, версии хватает.

## 🔄 4. Интеграции и Сложный Стек
