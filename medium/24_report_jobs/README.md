# Report Jobs

## 🎯 1. Описание Бизнес-Задачи
Тяжёлый отчёт не отдаётся в том же запросе. Он создаётся, продвигается тиками и скачивается только когда готов. Перевёрнутый диапазон дат падает сразу. Неготовый отчёт нельзя скачать.

## ⚙️ 2. Обоснование Архитектурного Выбора
Прогресс явный: 0, 50, 100. Так клиент видит, что работа идёт, и не получает пустой файл. Тик вместо настоящего воркера нужен, чтобы сценарий проверялся без ожидания.

## 🗄️ 3. СУБД и Хранилища Данных
Состояние отчёта в SQLite. Готовое тело короткое и лежит в той же строке. В бою файл ушёл бы в объектное хранилище, статус остался бы в таблице.

## 🔄 4. Интеграции и Сложный Стек
- Docker-порт `8124`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8124`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
