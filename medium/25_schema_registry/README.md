# Schema Registry

## 🎯 1. Описание Бизнес-Задачи
События меняют форму, а старые потребители не должны ломаться молча. Новая версия может добавить необязательное поле. Убрать обязательное поле нельзя. Проверка тела события говорит, каких полей не хватает.

## ⚙️ 2. Обоснование Архитектурного Выбора
Совместимость проверяется при регистрации, а не в каждом потребителе. Правило узкое: обязательные поля предыдущей версии должны остаться обязательными, известные поля нельзя выкинуть. Это не полный JSON Schema, но ломающее изменение видно до публикации.

## 🗄️ 3. СУБД и Хранилища Данных
Версии схем в SQLite. Поля хранятся списками. В бою реестр может жить отдельно от брокера, контракт тот же.

## 🔄 4. Интеграции и Сложный Стек
- Docker-порт `8125`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8125`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
