# Circuit Breaker

## 🎯 1. Описание Бизнес-Задачи
Если биллинг падает пачкой, витрина не должна долбить его каждым кликом. После трёх ошибок цепь открывается. Пока она открыта, повторный вызов не идёт в апстрим: отдаётся последний успешный ответ либо 503, если успешного ещё не было. Через 30 секунд допускается один пробный вызов. Успех закрывает цепь, ошибка открывает её снова.

## ⚙️ 2. Обоснование Архитектурного Выбора
Состояние цепи живёт в процессе: это машина состояний, а не таблица заказов. Часы подменяются через `POST /clock`, поэтому таймаут проверяется без ожидания. Апстрим — порт с режимом `fail`, а не внешний HTTP, чтобы сценарий шёл офлайн.

## 🗄️ 3. СУБД и Хранилища Данных
База не нужна. Кэш последнего успеха лежит рядом с состоянием цепи. Если таких процессов несколько, то же состояние выносится в Redis, правила closed / open / half-open не меняются.

## 🔄 4. Интеграции и Сложный Стек
- Порог: 3 ошибки. Окно восстановления: 30 секунд.
- Docker-порт `8106`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8106`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
