# CDC Projector

## 🎯 1. Описание Бизнес-Задачи
Запись в заказы не должна сразу менять витрину чтения. Изменение попадает в журнал, витрина обновляется отдельным проходом. Пока проход не вызван, витрина старая. Удаление тоже доходит до витрины только после проекции.

## ⚙️ 2. Обоснование Архитектурного Выбора
Журнал пишется в той же транзакции, что и заказ. Проектор читает непрочитанные строки и отмечает их. Это учебный CDC без WAL Postgres, но разделение «запись» и «витрина» настоящее: чтение из витрины не видит незапроецированное.

## 🗄️ 3. СУБД и Хранилища Данных
Заказы, журнал и витрина в одном SQLite. В бою журнал может быть logical replication, витрина — отдельная таблица или Redis.

## 🔄 4. Интеграции и Сложный Стек
- `POST /project` применяет хвост журнала.
- Docker-порт `8128`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8128`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
