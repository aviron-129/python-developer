# Audit Log

## 🎯 1. Описание Бизнес-Задачи
Действия пользователей нужно записывать так, чтобы их нельзя было тихо поправить. Журнал только дописывается. Каждая запись ссылается на хэш предыдущей. Поиск идёт по автору и действию. Изменение записи через API отклоняется.

## ⚙️ 2. Обоснование Архитектурного Выбора
Хэш-цепочка делает вставку в середину видимой: проверка проходит по порядку и сравнивает сохранённый хэш с пересчитанным. Это не замена электронной подписи, но ловит правку строки в таблице.

## 🗄️ 3. СУБД и Хранилища Данных
События в SQLite с уникальным `seq`. UPDATE из API нет. В бою таблица на PostgreSQL без права UPDATE у приложения.

## 🔄 4. Интеграции и Сложный Стек
- `GET /events/verify` пересчитывает цепочку.
- Docker-порт `8114`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8114`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
