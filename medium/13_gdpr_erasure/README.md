# GDPR Export and Erasure

## 🎯 1. Описание Бизнес-Задачи
Человек может забрать свои данные и потребовать удалить личность. Выгрузка собирает профиль и заказы. Стирание обнуляет имя и почту, но оставляет заказы: они нужны учёту, уже без персональных полей.

## ⚙️ 2. Обоснование Архитектурного Выбора
Стирание — это не `DELETE` пользователя. Заказы ссылаются на тот же идентификатор, а личные поля становятся пустыми и помечаются `erased`. Новая выгрузка после стирания уже не содержит почту.

## 🗄️ 3. СУБД и Хранилища Данных
Люди, заказы и снимки выгрузок в SQLite. Снимок фиксирует то, что было отдано. В бою те же таблицы на PostgreSQL.

## 🔄 4. Интеграции и Сложный Стек
- Docker-порт `8113`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8113`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
