# API Keys

## 🎯 1. Описание Бизнес-Задачи
Интеграции ходят не паролем пользователя, а ключом с ограниченным scope. Сырой ключ показывается один раз. Ротация делает старый секрет недействительным сразу. Отозванный ключ не проходит даже свой scope.

## ⚙️ 2. Обоснование Архитектурного Выбора
В базе лежит SHA-256 секрета и короткий префикс для поиска. Полный ключ не восстанавливается из строки таблицы. Проверка scope отделена от «ключ существует»: нет права — тот же отказ, что и у плохого секрета.

## 🗄️ 3. СУБД и Хранилища Данных
Ключи в SQLite. Префикс уникален, секрет не хранится. В бою та же таблица на PostgreSQL, Redis не обязателен, пока отзыв читается из базы.

## 🔄 4. Интеграции и Сложный Стек
- Формат ключа: `pk_<prefix>.<secret>`.
- Docker-порт `8112`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8112`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
