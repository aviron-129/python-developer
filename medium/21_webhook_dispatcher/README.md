# Webhook Dispatcher

## 🎯 1. Описание Бизнес-Задачи
Событие заказа нужно доставить подписчику с подписью. Если приёмник падает, доставка повторяется. После двух ошибок третья попытка проходит. Подпись считается от тела, чтобы получатель мог проверить, что его не подменили.

## ⚙️ 2. Обоснование Архитектурного Выбора
Повторы живут в диспетчере, а не в надежде, что получатель сам переспросит. Подпись — HMAC-SHA256 секрета подписки. Приёмник в этом сервисе локальный, с заданным числом отказов, чтобы сценарий шёл без чужого сервера.

## 🗄️ 3. СУБД и Хранилища Данных
Подписки и попытки доставки в SQLite. Секрет подписки нужен для подписи. В бою доставка идёт HTTP, журнал попыток тот же.

## 🔄 4. Интеграции и Сложный Стек
- До трёх попыток на событие.
- Docker-порт `8121`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8121`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
