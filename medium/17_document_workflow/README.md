# Document Workflow

## 🎯 1. Описание Бизнес-Задачи
Документ идёт по пути черновик, ревью, согласован, опубликован. Перепрыгнуть этап нельзя. Автор не может согласовать свой документ. Отказ возвращает его в черновик, а не в тупик.

## ⚙️ 2. Обоснование Архитектурного Выбора
Допустимые переходы заданы таблицей, а не цепочкой `if` в каждой ручке. Отдельное правило «автор не согласует» не смешано с графом статусов: сначала проверяется переход, потом роль.

## 🗄️ 3. СУБД и Хранилища Данных
Документы в SQLite, статус — строка из конечного набора. В бою та же машина состояний на PostgreSQL.

## 🔄 4. Интеграции и Сложный Стек
- Действия: submit, approve, reject, publish.
- Docker-порт `8117`. Проверка: `pytest test_main.py`.
- Контейнер: `docker compose up --build` из этой папки, порт `8117`.
- CI: `.github/workflows/medium-services.yml` на push запускает `pytest test_main.py` и `docker compose config`.
